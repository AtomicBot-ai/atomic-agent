# Recovery, progress and evidence

Status: current
Owner: src/agent/

## Distinct failures

Completion parse/validation recovery, transport retry, request-size repair and provider fallback are separate layers. Preserve their attempt budgets and cancellation semantics; a tool error is an ordinary result, not permission to replay its side effects. The streamed parser and unary repair must not emit an already committed delta twice.

A reply cut short (on llama-server, `stop_type: "limit"` without a context overflow counts as the reply cap) is retried by truncation repair with a notice to think less and write a large file in parts. Cloud keeps the cap (two retries per step); local raises it two-fold once, unless the reply ended in a loop. A local reply whose tail repeats one block exactly (at least 256 characters and 8 copies) is aborted mid-stream and retried the same way, at the same cap. A filled window repacks once per step; six retries over back-to-back cut steps end the turn.

Before that retry, an answer cut at a reply cap (not the window, not a loop) is [continued](../step/answer-continuation.ts) once inside the step: the partial `reply` text is quoted back with a request for the rest only, and the two are joined. A continuation cut again ends the step with what arrived plus a line saying it was cut; one that fails any other way throws the original truncation, and the turn-level retry above runs as before. Never more than one continuation per step. A local thinking profile under the untouched default `localModels.completionMaxTokens` runs under a [lifted cap](../step/thinking-reply-cap.ts) of 32,768 on grammar links, since its think block spends the same budget as the answer; a configured value or `ATOMIC_AGENT_LLAMA_MAX_TOKENS` is kept as is.

A request the model server refuses as too large for its context window (llama.cpp `exceed_context_size_error`, an OpenAI-style "maximum context length" 400/413) is compacted once per turn and the same step retried ([overflow compaction](../turn/overflow-compaction.ts)). The compaction plans against the window the server named (llama.cpp's body `n_ctx`, scaled by the agent's estimate over the server's `n_prompt_tokens` when the estimate undercounted), else most of the refused prompt's estimate; that window also drives the rest of the turn's automatic compaction, and only a window the server named is remembered (under the provider that refused) for later turns. A second refusal, or a compaction that frees no room, makes the turn's one `loop_failed` carry a plain "no longer fits this model's context window" error (the server's sentence stays on the cause), unless the turn was stopped or timed out or the refusal blames the reply reserve rather than the conversation. Each attempt and outcome is logged and a successful one emits `prompt_repacked`.

A turn uses bounded continuation legs and task-wide limits, not an unlimited inference loop. Progress policy includes repeated calls, result-aware no-progress, read coverage, repeated test commands, wandering and review stalls. Its warnings/refusals are dispatch behavior, not merely prompt suggestions. Graceful no-progress closure is distinct from infrastructure failure. User cancellation records a stopped-turn marker without emitting a second assistant reply; the next request and memory extraction treat the withdrawn task as closed. Ephemeral worker turns do not retain this marker. Subscription CLI installation/sign-in errors are setup failures, rather than waitable provider outages.

Loop gates key on the exact call: the repeat, no-progress and veto-streak counters belong to one `(tool, args)` signature, so a call failing over and over never blocks a different call that succeeds beside it (the composite batch observation only warns). An `os.fs.read` also carries the mutation epoch of its path: a write, edit, applied patch (targets from its diff headers; a dry run counts for nothing), move or restore attempted on that path, landed or failed, starts a new epoch, so the re-read a failed edit calls for is not a repeat (ATO-1000). After three failed attempts in a row on a path with nothing landed, further failures open no epoch, so identical re-reads between ever-different failing edits are vetoed again. The wandering run rule counts step rounds, not calls: distinct probes of one step, parallel or run in emitted order, are one round, and the window ceiling still bounds wide fan-outs across steps (ATO-999). The `tool executed` log line names, for an os.fs call, the path it acted on and, for a failure, the first line of its error, never file contents; any failure also logs a code-style error code such as `ENOENT` when there is one; other tools log only the error name and that code, since a shell error echoes its command line and output ([fields](../tool-log-fields.ts)).

A refused connection to the managed local model (`local-llama`, managed mode, the active text provider) whose process is certainly gone is not waited out either (ATO-772). The runtime reads the engine state from disk and hands it to recovery as `localEngineState`; recovery reads no files itself. While the process is gone the turn retries every 2 seconds for a short restart grace, so the TUI or desktop supervisor can bring back a model that crashed; then it ends with `LocalEngineDownError` ("The local model isn't running.", reason code `local_engine_down`). A live engine, a start or install under way, an external server, cloud links and `local-llama` as a fallback behind a cloud provider keep the ordinary wait.

A server error from the managed local model whose current run logged out of memory is not waited out either (ATO-334). The runtime reads the model's log and launch record and hands recovery `localOutOfMemory`; recovery returns `local_out_of_memory` and the loop runs `out-of-memory-recovery.ts`: restart the model with half the context window it ran with (never below 32 768 tokens, at most three restarts with no step completed between them) and replay the same step. A turn with someone watching the chat (`RunTurnOptions.localOutOfMemory: "ask"`: the TUI chat, a desktop chat) asks first through the approval surface (category `local_model_restart`, never granted for the session); an unattended turn (scheduled task, Telegram, Discord, headless run) restarts without asking. The smaller window holds until the model is next started; the config is not written. In the TUI that restart does not grow, and the growing auto window (ATO-848) stops at that size for the model for the rest of the process. Where nothing in the process can restart the model (a headless `serve`, whose model the desktop owns) the turn ends at once with the window to restart with. Every stop ends with `LocalOutOfMemoryError`, whose sentence says to pick a smaller model when a smaller window is not enough.

Every terminal failure names its cause from one shared list (ATO-384): [the failure catalog](../../llm/reliability/failure-catalog.ts) maps a stable `cause` id to a plain `phrase` and one `action` (`retry`, `switch-model`, `new-chat-summary`, `reduce-load`, `add-search-key`, `none`), and [its classifier](../../llm/reliability/classify-failure-cause.ts) picks the entry from the error's typed facts; a local server's typed HTTP answer follows its existing code ([local-server-error](../../llm/reliability/local-server-error.ts)): `local_context_exceeded` is `context_too_long`, `local_request_invalid` is `request_rejected`, a 404/405 is `local_server_not_found`, so `code` and `failure` on one frame never disagree. `loop_failed` carries it as `failure`, a tripped loop breaker's `loop_detected` carries `same_call_repeated` or `loop_detected`, and the HTTP extensions `error` frame carries it as `failure: {cause, phrase, action}` beside its existing fields. Hosts read the id and the button from there instead of matching the error sentence.

Evidence checks prevent unverified check claims, unsourced links and fabricated transcripts from becoming a closing answer. Keep actual observations as the basis for evidence. Read-scope and declared-input guards must survive both solo and batch paths.

## Ownership and asynchronous boundaries

[Turn recovery](../turn/turn-recovery.ts) returns synchronous decisions; the loop performs the existing provider-outage wait explicitly. [Preparation](../turn/turn-preparation.ts) surrounds the original memory/profile awaits. [Finalization](../turn/turn-finalization.ts) keeps completion events and steering drain order. A turn that closes `max_steps` never got the model's summary (the reserved final step overran its deadline or was refused), so its stop reply carries a [digest](../turn/pause-digest.ts) built from the turn's own records, with no model call. Adding an unconditional async wrapper would allow queued event callbacks to run before dispatch or turn closure, even when no recovery wait is needed.

Step parsing and repair preparation/finish are synchronous; the actual repair completion await remains in [step-executor.ts](../step-executor.ts). The one-shot repair runs under `repairReplyCap` ([step parsing](../step/step-parsing.ts)): 1024 tokens on a grammar link as an anti-loop guard, plus the enforced reasoning budget for a thinking profile (the step's cap when the budget is unbounded), and the step's cap on native tools. Stream consumption still owns iterator cleanup.

Before that repair completion, call JSON that does not parse gets one mechanical fix ([repair](../../llm/grammar/repair-tool-call-json.ts): code fences, single quotes, raw newlines in strings, trailing commas, an open string or brackets at the end, never after a bare number that may itself be cut), on the grammar body, nested `args` strings and native argument strings. [The step](../step/step-json-repair.ts) runs a repaired batch only when every call names a registered tool with schema-valid arguments; a repair that had to close a string is never used, and one that closed brackets is refused on a cut completion and for write, edit and patch. Each repair is logged ("tool-call JSON repaired" or "repair not used") with the fixes applied. A refused repair takes the one-shot repair path as before. [Progress helpers](../progress/README.md) are independent of the tracker state; [policies](../policies/README.md) do not own resources.
