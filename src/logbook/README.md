# Logbook

Status: current
Owner: src/logbook/

A day journal from screenshots (ATO-2363), described only by a model on this computer. Precedents: OpenClaw's logbook plugin (state in `<state-dir>/logbook/`) and Screenpipe; the difference here is that no screenshot ever reaches a cloud model. Screenshots and their descriptions are made locally; notes you ask about go to your active model, and `logbook.query` asks first when that model is not on this computer (below).

## Switch

Off by default. [Settings](logbook-settings.ts) live in `<stateDir>/logbook/settings.json` (`enabled`, `intervalMinutes` 1..60 default 5, `retentionDays` 1..365 default 14, `pausedUntil`, `excludeApps`, `titleOnlyApps`, `standupAt`), not in config.json, so there is no config version bump and the CLI can change them while the agent runs. `atomic-agent logbook start|stop|pause|resume|status|today|show|clear|exclude|title-only|standup` ([logbook-command.ts](../cli/logbook-command.ts), [logbook-command-more.ts](../cli/logbook-command-more.ts)) writes it. The TUI top bar shows `● logbook` while it is on and `◌ logbook paused` during a pause ([logbook-chip.tsx](../tui/components/logbook-chip.tsx)), re-read every 5 s. The desktop app shows `● Logbook` in its toolbar and a menu bar icon while it is on, with Pause, Resume and Stop on a click; it reads and changes the switch through [route-logbook.ts](../http/route-logbook.ts) (`GET /api/logbook`, `PATCH /api/logbook/settings`, the same changes as the CLI, [logbook-actions.ts](logbook-actions.ts), and the choices in [logbook-preferences.ts](logbook-preferences.ts)). Its Settings › Logbook edits every choice, and its day timeline lists a day's notes and deletes one or the whole day (`GET /api/logbook/day`, `DELETE /api/logbook/entries`, ATO-2526).

## Capture loop

[logbook-sidecar.ts](logbook-sidecar.ts) is a scheduler sidecar ([runtime-logbook.ts](../runtime/composition/runtime-logbook.ts)), so only the process that leads the scheduler captures, and only while a recording mark is on screen. A TUI process always shows one (its top bar). Any other process (the desktop's `serve`) captures only while its frontend reports its own mark on screen: the desktop sends `POST /api/logbook/indicator {visible: true}` every 15 s while its `● Logbook` chip or menu bar icon is shown, and the route writes `indicator.json` with that process's pid and a 45 s expiry ([logbook-indicator.ts](logbook-indicator.ts), ATO-2534). A report for another pid, an old one, or `visible: false` means hidden: no capture, and `status.json` says so once. `away: true` (idle or a locked screen) skips the frame. A frame whose mark went away while it was described is dropped. One-shot CLI runs get no report, so they never capture. Each tick re-reads settings; one capture per interval, never two at once; a frame described after a stop or pause is dropped. Retention deletes old day files once an hour, on or off. macOS, Windows and Linux (ATO-2526); on Linux only an X11 session can say which window is in front, so under Wayland every frame is skipped with a hint to log in to Xorg, and `GET /api/logbook` reports it unsupported.

[logbook-capture.ts](logbook-capture.ts), per frame: probe the window in front ([logbook-front-window.ts](logbook-front-window.ts): the JXA probe and `ioreg` idle time on macOS; on Windows one PowerShell program with `GetForegroundWindow`, `GetWindowText`, the process name and `GetLastInputInfo` ([logbook-front-window-win.ts](logbook-front-window-win.ts)); on X11 `xprop` or else `xdotool`, and `xprintidle` when present ([logbook-front-window-linux.ts](logbook-front-window-linux.ts))); skip the frame when nobody touched the mouse or keyboard for a whole interval (at least 5 min; the desktop also reports idle and a locked screen from Electron's powerMonitor); skip the app when [logbook-skip.ts](logbook-skip.ts) says so (password managers, login and security prompts, a locked screen, system settings, Atomic Agent, script runners, an unidentified app, the person's `excludeApps`; on Windows and Linux by process name or window class, `DESKTOP_PROTECTED_APPS`); for an app in `titleOnlyApps` ("describe less") store only the app and its window title, with no screenshot and no model call; otherwise take a silent screenshot into `<stateDir>/logbook/frames/` (0700) ([logbook-shot.ts](logbook-shot.ts): `screencapture -x` and `sips` on macOS, the screen tools' Windows and Linux capture elsewhere); probe again and throw the picture away if a protected app came to the front; describe with the local model (one or two sentences, no secrets asked for, then masked with the secret detector and capped at 400 chars); delete the picture in every case. Leftover frames from a crash are removed before the first capture.

[logbook-local-vision.ts](logbook-local-vision.ts): a provider is used only when its config entry is on loopback (`llama-server` with a loopback `url`, or none and a loopback `localModels.url`; any other kind with a loopback `baseUrl`, such as Ollama or LM Studio) and its model can see (`capabilities.vision`). The active provider is tried first. No such provider: no screenshot, and `status.json` says why. There is no cloud fallback.

## Storage and reading

[logbook-store.ts](logbook-store.ts): one JSON line per note (`at`, `app`, `bundleId`, `text`) in `<stateDir>/logbook/YYYY-MM-DD.jsonl` (0600), by local day. No image is stored. Delete whole days (`clear --all|--day|--before`) or a time range of one day (`clear --day <d> --from HH:MM --to HH:MM`). Delete chosen notes of a day by their `at` (`deleteLogbookEntries`, the desktop timeline). [logbook-status.ts](logbook-status.ts) keeps the loop's last outcome in `status.json`.

[logbook-query.ts](logbook-query.ts) turns `day` (today, yesterday, YYYY-MM-DD), `part` (morning 0-12, afternoon 12-18, evening 18-24), `from`/`to` and `contains` into a window; over the limit it samples evenly. The `logbook.query` tool ([tool](../tools/logbook/logbook-query-tool.ts)) is read-only, framed as untrusted outside data (the notes describe whatever was on screen), asks under `logbook_cloud` (silent only at full trust, never settled by the risk reviewer) when the model serving the step or any model in `llm.fallback.chain` is not loopback by the test above (`logbookNotesStayLocal`; a loopback model never asks), and its descriptor is offered only while the logbook is on or keeps notes (`GATED_TOOLS.logbook`). The [standup recipe](../recipes/standup-recipe.ts) asks the agent to call it. With `standupAt` set (`logbook standup --every-morning 09:00`, or the desktop's switch), the capturing process files one recurring cron task that runs the recipe for yesterday every day at that time, through the existing scheduler, and replaces or cancels it when the time changes or the logbook stops ([logbook-standup.ts](logbook-standup.ts), [runtime-logbook-standup.ts](../runtime/composition/runtime-logbook-standup.ts)); which task is ours is kept in `standup.json`. A task the person cancels in the task list is not filed again until the time changes.

Checks: `npx vitest run src/logbook src/tools/logbook src/cli/logbook-command.test.ts src/recipes/standup-recipe.test.ts`.
