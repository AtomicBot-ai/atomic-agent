# Privacy Shield

Status: current
Owner: src/privacy/

Masks personal data and keys before a request goes to a cloud model and puts them back on this machine (ATO-992 epic). Off by default: `privacy.shield.enabled` in config.json.

- [Detector](detect-private-data.ts): regex-first. `SECRET` reuses the shared credential detector ([secret detector](../error-reporting/secret-detector.ts)) by aligning its markers back to the text; `CARD` (Luhn), `IBAN` (mod 97), `EMAIL`, `PHONE` (international `+…` or a bracketed area code). Linear patterns only; a bare run of digits is never a phone. Regex is the floor: nothing below can remove or relabel what it finds.
- [Local name pass](local-name-detector.ts) (ATO-2394, opt-in `privacy.shield.localNames`): a LOCAL model finds `NAME`, `ADDRESS` and `ORG` spans and returns them as JSON ([prompt, GBNF and schema](local-name-prompt.ts)); a span the paragraph does not contain word for word is dropped. It refuses any model whose `local` is not `true` before reading the text, so unmasked text never goes to a cloud model for detection. Any error, timeout (8 s per request), bad JSON or missing local model adds nothing: the request goes out with the regex masks, as before. Paragraph spans are cached by SHA-256 in memory (512 paragraphs), so a growing chat only sends its new paragraphs; at most 4 calls of 4000 characters per request. Wired in [runtime-privacy-names.ts](../runtime/composition/runtime-privacy-names.ts): the active text provider when it runs on this machine, else the first provider that does. Loopback only (`localhost`, `127.0.0.0/8`, `::1`), judged by the URL completions really go to: `localModels.url` (and the entry's `url`, if set) for `llama-server`, `baseUrl` for `openai-compatible` / `qwen-openai-compatible`; every other kind is refused (`subscription-oauth` and `subscription-cli` ignore `baseUrl`). A server on the local network is not used, so the unmasked text never leaves this machine for detection. With none, the start-up log says names need a local model. Paragraphs are read newest message first, so a pass cut by the call cap or the budget skips older text, and the leftover count is logged as "N paragraphs left for later" (never the text). `</text>` inside the text (spaces or zero-width characters included) is defused so it cannot close the prompt's fence. A paragraph's answer is cached only when it proved a span, or when it was the only paragraph in the call: a "no names" from a shared call is used once, never kept. Precedents: PAPILLON (arXiv 2410.17127) and HazyResearch Minions privacy mode, where the local model redacts before the remote call.
- [Name value filter](name-value-filter.ts) (ATO-2527): between the local pass and the vault. Drops values on a keep list (titles, generic organisation words such as "support" or "Банк", chat roles, the tool names themselves) and any `ORG` with no capital letter and no digit, so an ordinary word is not masked in every later message (the `allow_list` idea of Microsoft Presidio). Adds each capitalised word of a multi-word `NAME` after the full name ("Иван Петров", then "Иван", "Петров"), so a name split across two content parts, or later written by first name alone, is still masked. A word of two letters, or one on a short stop list of greetings and given names that are everyday words ("Hi", "Will", "Max", "Роман", "Вера"), is not learned on its own, so "Max 5 results" stays readable; the full name is still masked. The tool name "Claude" is kept only when the model calls it an organisation: a person called Claude is masked.
- What the pass reads ([messageTextsForNames](../llm/provider/openai/openai-privacy-shield.ts), ATO-2527): user and tool messages (context summaries go out as user messages, so they count), never the system prompt (ours). Assistant replies are read once, on the first pass of the session's vault in this process, and skipped after that, because a later reply is the cloud's own text with the vault's values put back. That first pass covers the replies no vault saw: an imported session (Hermes, Codex, Claude Code, the Claude app, a handoff), the chat before an agent restart (vaults live in memory only, so the user message that held a name may sit past the 4 x 4000 character budget while a recent reply repeats it), and replies a local model wrote before the first cloud request. A pass counts only once it read the texts (no local model or the switch off does not use it up). Known gaps: replies past the first pass's budget are not read later; a reply a local model wrote between two cloud requests of the same chat (cloud, then local, then cloud) is not read, though names it took from a tool result are still masked because that tool result is read. The text parts of one message are read as one text.
- Status for the Privacy tab ([runtime-privacy-names-status.ts](../runtime/composition/runtime-privacy-names-status.ts)): `off`, `ready` (a model on this machine is configured; if it is not running, the request goes out with the regex masks), `no-local-model`, or `provider-not-shielded` (the active chat provider is a ChatGPT sign-in or a Claude Code / Codex CLI, which Privacy Shield does not wrap, so nothing is masked for it), plus the provider and model the pass would use. `runtime.privacyShield.localNames` persists the switch; `/api/privacy-shield` reports and sets it; the TUI Privacy tab uses `n`.
- Quality benchmark: `npm run eval:privacy-names` (50 made-up letters, 25 English and 25 Russian, in `eval/fixtures/privacy-names/`) runs the real pass against a server on this machine, checks that the server takes the GBNF grammar with its bounded repeats, and reports recall, precision and latency for tuning the prompt, the 8 s budget and the chunk size. Not part of `npm test`; its scoring is (`eval/harness/privacy-names/`).
- [Vault](privacy-vault.ts): per-session reversible map. Each value gets a stable placeholder (`[EMAIL_1]`, `[CARD_1]`, `[SECRET_1]`), the same one every time, so a cloud prompt cache keeps hitting. A value masked once is masked wherever it shows up again. `unmask` restores only placeholders this vault minted; `{ json: true }` inserts values JSON-escaped for tool-call arguments. Values from the local name pass come in through `learn` (`[NAME_1]`, `[ADDRESS_1]`, `[ORG_1]`) and are masked after the regex spans, as whole words (`Иван` not inside `Иванов`); `learn` refuses a value the regex detector finds data in or the vault already holds. In memory only, never written to disk.
- [Stream unmasker](stream-unmasker.ts): holds back a tail that could still be a placeholder cut between two chunks (`[EMA` + `IL_1]`).
- [Registry](privacy-vault-registry.ts): one vault per session id and the process-wide "masked N" totals. A Fusion worker's session is linked to its chat's vault (ATO-1083); deleting a session forgets its vault and links.

Applied by [the OpenAI-compatible provider](../llm/provider/openai/openai-privacy-shield.ts) (ATO-1081), which every API-key cloud provider is. Not applied to `subscription-oauth` (ChatGPT sign-in) or `subscription-cli` (Claude Code, Codex CLI): those send the text as it is; `isPrivacyShieldEnabled` is the process switch, set from config at startup. Before the body is masked, `learnNamesForRequest` awaits the local name pass (when one is installed with `setPrivacyNameDetector`) so the sync mask covers its values too.

Contract: masking applies only to cloud requests; local models (llama.cpp, managed Atomic Core, a server on this machine or the local network) always get the real text. Session history keeps the real text. Precedents: Hermes vault handles (the model holds a handle, the local side the value) and Perplexity Personal Computer masking before the cloud step.

Checks: `npx vitest run src/privacy`; `npm run lint`; `npm run docs:check`.
