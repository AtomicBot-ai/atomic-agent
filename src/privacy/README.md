# Privacy Shield

Status: current
Owner: src/privacy/

Masks personal data and keys before a request goes to a cloud model and puts them back on this machine (ATO-992 epic). Off by default: `privacy.shield.enabled` in config.json.

- [Detector](detect-private-data.ts): regex-first. `SECRET` reuses the shared credential detector ([secret detector](../error-reporting/secret-detector.ts)) by aligning its markers back to the text; `CARD` (Luhn), `IBAN` (mod 97), `EMAIL`, `PHONE` (international `+…` or a bracketed area code). Linear patterns only; a bare run of digits is never a phone. Regex is the floor: nothing below can remove or relabel what it finds.
- [Local name pass](local-name-detector.ts) (ATO-2394, opt-in `privacy.shield.localNames`): a LOCAL model finds `NAME`, `ADDRESS` and `ORG` spans and returns them as JSON ([prompt, GBNF and schema](local-name-prompt.ts)); a span the paragraph does not contain word for word is dropped. It refuses any model whose `local` is not `true` before reading the text, so unmasked text never goes to a cloud model for detection. Any error, timeout (8 s per request), bad JSON or missing local model adds nothing: the request goes out with the regex masks, as before. Paragraph spans are cached by SHA-256 in memory (512 paragraphs), so a growing chat only sends its new paragraphs; at most 4 calls of 4000 characters per request. Wired in [runtime-privacy-names.ts](../runtime/composition/runtime-privacy-names.ts): the active text provider when it runs on this machine, else the first provider that does. Loopback only (`localhost`, `127.0.0.0/8`, `::1`), for every kind: a server on the local network is not used, so the unmasked text never leaves this machine for detection. With none, the start-up log says names need a local model. Paragraphs are read newest message first, so a pass cut by the call cap or the budget skips older text, and the leftover count is logged (never the text). `</text>` inside the text is defused so it cannot close the prompt's fence; an empty answer for a multi-paragraph call is used but not cached. Precedents: PAPILLON (arXiv 2410.17127) and HazyResearch Minions privacy mode, where the local model redacts before the remote call.
- [Vault](privacy-vault.ts): per-session reversible map. Each value gets a stable placeholder (`[EMAIL_1]`, `[CARD_1]`, `[SECRET_1]`), the same one every time, so a cloud prompt cache keeps hitting. A value masked once is masked wherever it shows up again. `unmask` restores only placeholders this vault minted; `{ json: true }` inserts values JSON-escaped for tool-call arguments. Values from the local name pass come in through `learn` (`[NAME_1]`, `[ADDRESS_1]`, `[ORG_1]`) and are masked after the regex spans, as whole words (`Иван` not inside `Иванов`); `learn` refuses a value the regex detector finds data in or the vault already holds. In memory only, never written to disk.
- [Stream unmasker](stream-unmasker.ts): holds back a tail that could still be a placeholder cut between two chunks (`[EMA` + `IL_1]`).
- [Registry](privacy-vault-registry.ts): one vault per session id and the process-wide "masked N" totals. A Fusion worker's session is linked to its chat's vault (ATO-1083); deleting a session forgets its vault and links.

Applied by [the OpenAI-compatible provider](../llm/provider/openai/openai-privacy-shield.ts) (ATO-1081), which every cloud provider is; `isPrivacyShieldEnabled` is the process switch, set from config at startup. Before the body is masked, `learnNamesForRequest` awaits the local name pass (when one is installed with `setPrivacyNameDetector`) so the sync mask covers its values too.

Contract: masking applies only to cloud requests; local models (llama.cpp, managed Atomic Core, a server on this machine or the local network) always get the real text. Session history keeps the real text. Precedents: Hermes vault handles (the model holds a handle, the local side the value) and Perplexity Personal Computer masking before the cloud step.

Checks: `npx vitest run src/privacy`; `npm run lint`; `npm run docs:check`.
