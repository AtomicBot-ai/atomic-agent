# MCP lifecycle, trust, sampling and elicitation

Status: current
Owner: src/mcp/

McpManager owns configured client lifecycle and dynamic registry entries; restart/shutdown must remove the corresponding tools/catalog. Client transports and SDK usage belong to the client boundary. Per-server `enabledTools` / `disabledTools` drop tools at discovery (`mcp-tool-filter.ts`), so a turned-off tool is absent from the catalog, descriptors, grammar and registry. Per-server trust determines resource classification; third-party schemas cannot be assumed to share built-in flat shapes.

Resources and prompts are discovery/read tools, while sampling forwards an isolated completion rather than taking the main turn's slot. Stdio transport passes only an allowlist of service variables from the agent environment ([mcp-stdio-env.ts](../mcp-stdio-env.ts): PATH, HOME, locale, temp and XDG dirs, display, SSH agent socket, Docker host, Windows profile/system variables such as SystemRoot, APPDATA, USERPROFILE, ComSpec, PATHEXT and PSModulePath, proxies and CA bundles), matched case-insensitively, then overlays the server's configured `env`, which wins. Provider keys and bot tokens loaded from the state-directory .env are not forwarded; a server that needs a key must list it in its own `env`. This is environment hygiene, not a sandbox: the subprocess still runs as the user and can read files the user can. Preserve credential redaction in stderr/errors and explicit unsupported-operation refusals. Do not add credential-shaped names to the allowlist.

HTTP transports (streamable HTTP and SSE) keep the SDK's default redirect policy: since SDK 1.32 a redirect is followed only within the configured endpoint's origin (an http to https upgrade on the same host is allowed only when both use the default port). A server whose URL redirects to another host or port must be configured with its final URL. We do not set `redirectPolicy: 'follow'`, so a cross-origin redirect fails instead of sending configured headers to another origin.

Elicitation (ATO-704) lets a server ask the person for input in the middle of a call: pick an account, confirm an action, fill a small form. A client advertises `elicitation: {}` (form mode only) only when the host wires an "ask the human" port, `RuntimeEventHandlers.onMcpElicitation`, which reaches McpManager as `elicitationPort`; with no port no client advertises it, and a spec-following server will not send `elicitation/create`. The manager gives every client its own handler ([mcp-elicitation-handler.ts](../mcp-elicitation-handler.ts)) so the person always sees which server is asking. The handler accepts only a flat form of primitive fields ([mcp-elicitation-schema.ts](../mcp-elicitation-schema.ts): string with optional length and email/uri/date/date-time format, number or integer with a range, boolean, single-select and multi-select enums, at most 20 fields); anything else and URL mode are declined without asking. A reply from the port is checked against the form ([mcp-elicitation-answer.ts](../mcp-elicitation-answer.ts)) before it goes back. Invariants: never auto-accept, since `accept` only comes from the port; the turn never breaks, so a missing surface, an unattended run (the port answers `unavailable`), a port error or garbage reply is `decline`, and a timeout (5 minutes), a server cancel or an answer that does not fit the form is `cancel`; answers never reach logs or traces, because the handler logs only server, action, reason and field count, and validation reasons name fields, not values. Fields whose name or title looks like a credential carry `sensitive: true` so a surface masks them. The port is called outside any turn frame: the host decides whether a person is there. Today no host wires a port (TUI, desktop, Telegram and Discord are follow-ups), so behaviour is unchanged until one does.
