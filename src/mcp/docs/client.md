# MCP lifecycle, trust and sampling

Status: current
Owner: src/mcp/

McpManager owns configured client lifecycle and dynamic registry entries; restart/shutdown must remove the corresponding tools/catalog. Client transports and SDK usage belong to the client boundary. Per-server `enabledTools` / `disabledTools` drop tools at discovery (`mcp-tool-filter.ts`), so a turned-off tool is absent from the catalog, descriptors, grammar and registry. Per-server trust determines resource classification; third-party schemas cannot be assumed to share built-in flat shapes.

Resources and prompts are discovery/read tools, while sampling forwards an isolated completion rather than taking the main turn's slot. Stdio transport passes only an allowlist of service variables from the agent environment ([mcp-stdio-env.ts](../mcp-stdio-env.ts): PATH, HOME, locale, temp and XDG dirs, display, SSH agent socket, Docker host, Windows profile/system variables such as SystemRoot, APPDATA, USERPROFILE, ComSpec, PATHEXT and PSModulePath, proxies and CA bundles), matched case-insensitively, then overlays the server's configured `env`, which wins. Provider keys and bot tokens loaded from the state-directory .env are not forwarded; a server that needs a key must list it in its own `env`. This is environment hygiene, not a sandbox: the subprocess still runs as the user and can read files the user can. Preserve credential redaction in stderr/errors and explicit unsupported-operation refusals. Do not add credential-shaped names to the allowlist.

HTTP transports (streamable HTTP and SSE) keep the SDK's default redirect policy: since SDK 1.32 a redirect is followed only within the configured endpoint's origin (an http to https upgrade on the same host is allowed only when both use the default port). A server whose URL redirects to another host or port must be configured with its final URL. We do not set `redirectPolicy: 'follow'`, so a cross-origin redirect fails instead of sending configured headers to another origin.

## Browser sign-in (OAuth)

Remote servers that only allow OAuth (for example Monid) sign in through the browser, the way Claude Code and Codex do. Every Streamable HTTP / SSE transport gets an OAuth provider ([mcp-oauth-provider.ts](../mcp-oauth-provider.ts)) unless its `headers` already carry a credential (`Authorization`, or a name containing api-key, token, secret or password); those servers keep sending their headers exactly as before. A server that never answers 401 is unaffected. stdio is unchanged. The provider takes one type from the SDK; its `auth()` call is `runMcpOAuth` in the client, so SDK calls stay in mcp-client.ts.

When a connect gets a 401 and no usable token, the client throws `McpAuthRequiredError` and the manager sets the new state `needs_auth` (status `authRequired: true`, `lastError` "Sign in required") instead of `down`. The connect may register the client (dynamic client registration) but never records a verifier or URL, so a restart cannot spoil a sign-in in progress. Saved tokens are sent as `Authorization: Bearer` and refreshed by the SDK.

The sign-in itself is [mcp-oauth-flow.ts](../mcp-oauth-flow.ts), shared by HTTP (`POST /api/mcp/servers/{name}/auth/start` → `{ state: "pending", authUrl }`, `GET .../auth` → `{ state: "signed_out" | "pending" | "signed_in", error? }`, `POST .../auth/signout`) and the TUI (`/mcp auth <name>`, `/mcp signout <name>`). The agent never opens a browser: it may be headless, so the UI that asked opens `authUrl`. The flow opens one loopback listener on 127.0.0.1 for the callback path only, port 47613 first, then the next four, then any free port; the redirect URI is `http://127.0.0.1:<port>/callback`. The client registration is saved with the redirect it used and repeated when the port differs. `state` is random per request and a callback with any other value is refused. After a valid callback the code is exchanged, the browser gets a short "you can close this tab" page and the server is reconnected. A sign-in not finished in 5 minutes expires and the listener closes when none is left.

Credentials live in `<stateDir>/mcp-oauth/<name>.json` ([mcp-oauth-store.ts](../mcp-oauth-store.ts)), mode 0600 in a 0700 folder, written atomically. A record keeps the server URL: a changed URL reads as signed out and the next save replaces the old record. Sign out deletes the file. Tokens never go to logs or errors. An authorization server that refuses dynamic client registration cannot be signed in to yet: there is no field for a pre-registered client id.
