# Reliability and provider fallback

Status: current
Owner: src/llm/

## Responsibilities

Transport retry handles transient request/open failures: at most three attempts with jittered backoff, stretched to a provider's `Retry-After` up to 5 s. A cooldown longer than that is not retried in place (it would only spend requests against the same limit); the error goes up so the turn's outage wait honours the full hint within `agent.providerWait.maxWaitMs`, or the person's fallback link answers (ATO-483). A switch to a fallback link is always said in the turn: the `provider_switched` event carries the failure-catalog cause and the fallback model, and hosts show `falloverSentence` ("OpenRouter is rate-limited, switched to Gemini (gemini-2.5-flash)."; the SSE `atomic.provider_switched` frame's `notice`). Beyond that, parse recovery belongs to the step executor. Targeted credit-limit and structured-output repairs modify only their narrowly identified refusal. Do not broaden these into retries of arbitrary deterministic errors.

The chain holds only links the person picked: the active provider plus `llm.fallback.chain`. The local llama-server provider is appended only when `llm.fallback.appendLocal` is true (default false, ATO-349/ATO-892): a cloud error must surface as its own reason (`failure-catalog.ts`: phrase plus one action, `fix-key` for a refused key) rather than a silent switch to, or a wait on, a local model nobody chose.

The daily spend ceiling (`llm.costTracking.dailyLimitUsd`, ATO-649) refuses a paid link in the seam's per-attempt hook before anything is sent ([error](../reliability/spend-limit-error.ts)). `llm.costTracking.onDailyLimit` decides the rest: `"stop"` (default) does not advance, so the turn ends on "Daily cloud limit reached: $X of $Y. Cloud calls are paused until tomorrow." (failure cause `daily_limit_reached`) and every later paid call that day is refused the same way; `"local"` advances to the next link, the local model when the chain has one, and the switch notice says so (`cause: "spend-limit"`). Local and plan-billed links are never refused.


A turn the model router routed (`llm.router`, ATO-483) runs on that session's chain with the routed provider put first for the turn (`setTurnPrimary`), the configured links after it: a failure of the routed provider falls over to the next link like any primary's. Changing that head drops the session's sticky override, as a new primary does.

The local-first cascade (`llm.fallback.localFirst`, default false, ATO-2208) uses the same seam the other way round: a normal chat turn whose active provider is a cloud one starts on the first configured `llama-server` provider ([decision](../fallback/local-first-head.ts), wired in [runtime-turn-router](../../runtime/composition/runtime-turn-router.ts)), and a failure `shouldAdvance` accepts sends the same turn on to the active cloud provider and the rest of the chain, announced like any fallover and still under the daily spend ceiling. A matching router rule wins over it. It does nothing under Fusion, for a pinned turn, when the active provider is already local (put the cloud provider in `fallback.chain` for that cascade), or when the local link is not built, has no model on disk, or says it cannot do tools (or see an image the message carries). It also leaves the turn in the cloud (`too-long`, ATO-2537) when the local prompt build would compact the session ([fit](../../runtime/composition/local-first-fit.ts)): the prompt and compaction are sized to the turn's head, so a long cloud session started on a small local window would be compacted down to it. Like the compaction trigger, it compares the session's history (transcript, context summary and the new message, from the last prompt) with `agent.compaction.triggerRatio` of the local history allowance: the window minus the last prompt's fixed part, the reply reserve and the safety margin. The window is the live profile's, else the catalogue's, else for the managed link the running model's launch size or a fixed `localModels.managed.contextSize` ([window](../../runtime/local-first-window.ts)); right after a restart none may be known, and then a history over 8k tokens stays in the cloud. A later local link whose window fits is taken instead; a session that never built a prompt starts local. A local head that failed (any failure `shouldAdvance` accepts, a timeout included) rests before it heads a turn again (`cooling-down`, ATO-2435, [turn-head-cooldown](../fallback/turn-head-cooldown.ts)): 1 minute after the first failure in a row, 5 after the second, 15 after that, per session, cleared when it answers again. The head is put first again on every turn, so the breaker's own cooldown, which only steers the sticky override, never kept a hanging local server off the next turn.

The fallback breaker reads live chain configuration and partitions mutable state by session. Memory runners use distinct session identities; pinned worker turns bypass fallover. An appended local fallback is still omitted when no model weights are available, avoiding a wait for a daemon that cannot start; [availability](../../runtime/local-link-availability.ts) owns this check. Provider selection/probing is lazy and owns no periodic timer. A changed active provider affects subsequent resolution rather than a captured boot-time value.

## Several keys per provider

A provider entry may hold more keys besides `apiKey` (ATO-471). Like `apiKeyEnvVar`, they are referenced by env var name in `extraApiKeyEnvVars` and their values live in `<stateDir>/.env`; config.json never holds a key value, and a value that is not an env var name is refused. When `apiKey` is blank the first extra key is the one sent. The [key pool](../fallback/key-pool.ts) is one more level inside a chain link: when the service refuses a key (`keyRefusalKind`: a rate limit, a refused key, an empty account) the same request goes out with the next key of that provider, and only when every key was refused does the error reach the chain. The pool stays on the key that last served until it is refused, so a turn does not hop between keys. Each refused key cools down on the breaker ladder (rate limit 1/5/15 min or the provider's longer `Retry-After`; refused key or empty account 30 min). That state is process-wide, keyed by provider id and a hash of the key, because a limit belongs to the key, not to a session. A stream's shared attempt budget still bounds one completion. One distinct key means no pool, and the single-key path is unchanged. Keys never appear in logs; the notice names a key by position.

## Streams and transport

Opening/priming a stream can fail over before committed output. Once output is committed, restarting risks duplicating visible text or side effects. Cancellation must propagate as cancellation rather than advancing the provider chain.

Fallback completions and chunks carry servedTransport. Parsing and live reasoning detection use the actual serving link, including when a native-tools primary falls back to grammar. The primary's capabilities are not proof of what the fallback served. Cross-provider strict/parallel capability handling and grammar-primary/native-tail payload limitations remain explicit implementation constraints.
