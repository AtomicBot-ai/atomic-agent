# Error reporting

Status: current
Owner: src/error-reporting/

Owns outbound error scrubbing/report envelopes and failure-safe delivery. Scrub credentials before external reports; local traces have a different privacy contract.

Entry point: [error-scrubber.ts](error-scrubber.ts). [Secret detector](secret-detector.ts) is the shared credential masker (vendor key shapes, PEM keys, URL passwords, secret-named pairs, exact known values) behind the scrubber's allowlisted message and the masking of tool output before the model reads it (`src/tools/tool-output-secrets.ts`); its patterns stay linear and leave hashes, UUIDs and base64 alone. [Process secrets](process-secrets.ts) holds values known only in memory, today the key `serve` runs with (ATO-1705), which `runtimeKnownSecrets`, the result compressor and the step's trace masking add to their exact values; serve also removes `ATOMIC_AGENT_API_KEY` from its environment once read, so no child process inherits it (this stops inheritance only: the launch environment stays readable by the same user through `/proc/<pid>/environ` or `ps eww`). [LLM failure tags](llm-failure-tags.ts) reduce the runtime's `llm_failure` turn context (provider, local engine, outage wait, engine process state, and the failed request's route and port class, never its address or port number; for a refused connection also whether the engine process was alive and a bucket of how long the turn waited; `port_holder: other_process` for a 401 on the managed port with our engine not running, ATO-1277, which since ATO-2418 also carries the engine liveness, lock and exit reason a refusal carries; `managed_port` (`default` or `custom`) for either; the failed step's prompt budget by part, `prompt_total_tokens`, `prompt_prefix_tokens`, `prompt_tools_tokens`, `prompt_history_tokens`, `prompt_window`, `prompt_reply_reserve`, and a truncated reply's server counts, `cut_prompt_tokens`, `cut_reply_tokens`, `cut_reply_cap`, ATO-1678; a model failure's `finish_reason`, `reasoning_present`, `served_prompt_tokens`, `served_reply_tokens` and `server_kind` (`ollama` / `llama_server` / `other`), [completion facts](completion-facts-tags.ts), ATO-2421; a context-size refusal's `overflow_server_window`, `overflow_server_prompt_tokens` and `overflow_compaction`, ATO-2420) to fixed words and counts; anything outside a vocabulary is sent as `unknown`, and these tags stay out of the fingerprint. [Subscription CLI tags](subscription-cli-failure-tag.ts) add `cli_failure` (a fixed word such as `timeout`, `limit_reached`, `not_signed_in`) and `cli_exit_code` for a failed Claude Code or Codex run (ATO-1446), plus `cli_reason` (`unknown_option`, `git_bash_missing`, `node_missing`, `command_not_recognized`, `path_not_found`, `context_overflow`, `vendor_unavailable`, `no_output` or `other`, read from the CLI's text on the machine, ATO-1679, ATO-2417), never its stderr, binary or path, also outside the fingerprint. [Rate limit](sentry-rate-limit.ts) drops an event once the same grouping key (the fingerprint the envelope attaches, from `buildFingerprint`) was sent 10 times in the last hour by this install; the counter is kept in `sentry-rate-limit.json` in the state dir (key hashes and timestamps only) so restarts do not reset it. [Upstream error detail](upstream-error-detail.ts) reads a provider refusal's body on this machine and sends only `upstream_reason` (a fixed word such as `missing_thought_signature`, `tool_result_missing`, `empty_content`, or `other`), `upstream_error_param` (the blamed request field, only from a known root such as `messages` or `tools`, indices as `[]`, nothing below a schema's `properties`) and `upstream_error_code` (bounded enum shape), never the provider's sentence (ATO-1673); `upstream_reason` is also a fingerprint element after `upstream_error_type`, added only when present, so a 402, a 404 and our own bad request group apart (ATO-1687), while param and code stay tags only. A turn that failed on Atomic Chat's API key protection (`atomic_chat_key_required`, ATO-1274) is the person's to fix and already told in plain words, so the runtime does not report it. Nor does it report a turn the unknown-tool streak ended on a near miss (`ToolExecutionError` with `kind: "unregistered"` and `nameClass: "near_miss"`, ATO-1674): every such call was already answered with the closest real tool names, so it is a model mistake the agent handled ([check](../llm/reliability/unregistered-tool-failure.ts)). A streak on an `mcp_like` or `other` name still reports with its `tool_name_class` tag, since it can be a tool the prompt shows but the registry lacks, plus `tool_known_elsewhere` (`prompt_advertised`, `gated_off`, `mcp_server_missing`, `mcp_tool_missing` or `not_in_catalog`, ATO-2423; a `prompt_advertised` near miss reports too); any other tool failure still reports. A fusion worker stopped on purpose is not reported either ([fusion stop](fusion-stop.ts), ATO-1677): a turn's money or time cap reached (`FusionBudgetStopError`), or one worker stopped by the person, replaced by the escalation model, handed back early, or cut by the escalation run's time limit or spend cap (`FusionWorkerStopError`), matched by name anywhere in the `cause` chain; a real `RequestTooLargeError` still reports. A subscription CLI's account state is not reported ([check](subscription-cli-expected.ts), ATO-2417): a signed-out or expired login (`SubscriptionCliAuthError`), a spent usage limit (`limit_reached`) or a plan without the CLI (`plan_required`); the turn already says what to do, and every other CLI failure still reports. An unhandled rejection that is a reset or close of a socket whose peer is proven loopback (a local model server restarting) is not reported; the peer is proven from the error's own address, or, for a raw read reset that carries none, from the mark the agent's HTTP pool puts on every socket it opens to a loopback address ([loopback socket mark](../llm/loopback-socket-mark.ts)); an uncaught one still is, since it ends the process, except under `serve`, whose `loopbackReset: "survive"` policy writes one stderr line and keeps running without a report or an exit, since the request on that socket already failed through its own path ([loopback reset](loopback-reset.ts), ATO-2767; every other uncaught error, and every CLI command, keeps the fatal exit 1); global socket failures that report carry `socket_error_code`, `socket_peer` (`loopback`, `remote`, `unknown`) and `undici_frame`, never an address or port, outside the fingerprint ([socket error](socket-error.ts), ATO-1735). Read the root instruction route and the underlying domain instructions before cross-domain changes.

[Failure owner](failure-owner.ts) adds `failure_owner` to an `llm_failure` with an HTTP error status: `person` (cloud 401/403, 402, 404, 413, 429, or `key_refused`, `out_of_credit`, `model_not_found`, `request_too_large`), `ours` (a reason naming a part of the request we built), `provider` (5xx, 408) or `unknown` (anything else, and a 401/403 from a local server); read from the status and `upstream_reason` on the machine, a tag only, nothing stops being reported (ATO-2419).

[Grammar failure tags](grammar-failure-tag.ts) add `grammar_path` (`server_refused_grammar`, `server_refused_request`, `parse_failed`, `repair_failed`) to a `GrammarError` and, for `repair_failed`, `grammar_skipped` (`yes` / `no`), outside the fingerprint (ATO-2422).
