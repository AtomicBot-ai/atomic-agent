# Fusion workers

Status: current
Owner: src/tools/fusion/

Fusion delegates bounded task waves to worker turns. Contracts carry deliverables, declared inputs and dependencies; completed providers order later waves even when their task failed. Preserve task status attribution and hand-back based on completed-step progress rather than an independent timer.

Workers are ephemeral: no durable session row/reflection/trace; no recursive delegation or invisible interactive approval. Provider pins must not fall over to a different billing/model leg. Declared input replacement remains forbidden. A worker's approval-gated call is refused by its session policy. A fan-out's directory covers its writes and ordinary commands there, never a dangerous command (`shell_dangerous`), the agent's own config or secret files (`trust_config`, `state_secret`), mail, passwords or payments: those are refused with `FUSION_WORKER_OPERATOR_ONLY_REFUSED`, and the task comes back `needs_orchestrator` with a note telling the orchestrator to hand the step to the user instead of re-sending it (ATO-1222, ATO-1223). A fan-out whose write scope lies inside the agent's own state directory (`~/.atomic-agent`) is refused before the operator is asked, and the worker brief says an operator-only refusal is reported, not sent back for a re-send (ATO-1267). Concurrency is resolved from the call, task count and serving slot capability, rather than blindly capturing startup state.

After a local worker is cut off (time limit, queue wait, hand-back or operator cancel), the next local dispatch first asks the server `GET /health` ([local-leg-health.ts](local-leg-health.ts), ATO-917); a server that does not answer fails the task at once with a restart hint instead of letting it wait out its budget. A server that does answer gets the worker on fresh connections: the process's HTTP pool is swapped for a new one first (`renewTransportPool`, ATO-1357), the part of an agent restart that cleared the field case, while requests already in flight keep their sockets. A worker that still gets no token while `/slots` shows every slot idle is told the request got stuck on the agent's side, not to restart the server.
Worker spend is priced per completion with the prompt-cache discount (`estimateUsageCostUsd`, ATO-918). With `llm.runMode.fusion.turnBudgetUsd` / `turnTimeBudgetMs` set, [turn-budget.ts](turn-budget.ts) caps a fusion turn (ATO-947): reset at the turn's start, checked before a delegation, before each worker starts and on every worker completion; reaching it stops running workers and returns a plain-words instruction to the orchestrator. Unset, none of it runs.

[failure-breaker.ts](failure-breaker.ts) stops a fan-out that keeps failing the same way (ATO-1406): one blocker (tool-call protocol mismatch, CLI missing or signed out, out of credit) or `REPEAT_FAILURE_STREAK` identical failures in a row on a leg, and no new task starts there; running workers finish. Trips are kept on the turn's `FusionTurnBudget`, and a later delegation is refused on a leg that hit a blocker, or after the same repeat stopped two rounds. The same state counts rounds and tasks against `maxRoundsPerTurn` / `maxTasksPerTurn` (defaults 6 / 48, `0` off), checked before the fan-out's approval; the approval line names the round and the task count. Both need the runtime's per-turn `turnBudget`.

[worker-fit.ts](worker-fit.ts) checks a task's size against its worker's limit (ATO-1363): a task may state `outputTokens` or `outputLines` (optional, bounded; lines count as 10 tokens). On a local worker leg with a measured speed, tokens / tok/s × the workers running at once over the task's time limit puts a `fit:` warning on its row and the task still runs; it is refused before the approval only when, even running alone, it needs more than `FIT_REFUSE_FACTOR` (4) × its limit and more than the longest limit a task may ask for. Speed unknown: no check. The estimate also sizes the worker's time limit when it is bigger than the per-file guess (`estimateWorkerTimeoutMs`), and every task that carried an estimate gets an "Estimates vs actual" line (tokens out, time) in the result and `details.estimates`. The `### fusion` block states a local worker's step budget and time limit.

[escalation.ts](escalation.ts) escalates a stuck worker (ATO-942): with `escalation: "advisor"`, the first stall or cut first answer asks `ResolvedRunMode.escalation` (a configured provider other than the worker leg) for a hint at most `ADVISOR_MAX_OUTPUT_TOKENS` long, refused when its worst case is over `escalationMaxUsd`, and steers the worker with it. A later stall re-runs the task on that model only with `escalationReplace`. `FusionLiveWorkers` exposes the person's stop / escalate / steer per running worker (ATO-66, ATO-568), keyed by parent session and task id; a person's note rides the shared steering inbox under the worker's ephemeral session id and is read at its next step boundary. `src/http/route-fusion-workers.ts` puts the same three calls on HTTP for the desktop. Escalation spend is added to the turn's cap and reported per row and per fan-out.

[judge.ts](judge.ts) is the trimmed judge (ATO-944, `judge: "on"`): an acceptance list per task, rendered read-only into its brief (`briefSuffix`); after the waves, facts (check outcomes, provide presence, declared files) decide their items and can only be red or green on their own; a fresh-context judge (no transcript; files, or the reply when no file was declared) rules on the rest, and only a literal `pass: true` passes. A red list re-runs the task once with the findings; the contract is re-evaluated on the retried rows only. Unreadable or impossible judging leaves the task `needs_orchestrator`, never `ok`.

[replan.ts](replan.ts) is automatic replanning (ATO-941, `autoReplan: N`): dependents of a provider that did not close are held (`not started: held for the replan`), attempts per task are counted per turn in `FusionTurnBudget`, and `details.replan` lists pending and exhausted tasks; `src/agent/fusion-replan.ts` holds the planner's next step to `fusion.delegate` while any are pending, for at most two steps without a fan-out.

[role-models.ts](role-models.ts) is models by role and node (ATO-943): `llm.runMode.fusion.roles` maps `plan / build / review / explore / utility` to configured providers (one entry = one model). A task's `model` (must be the worker leg or a role model, else the call is refused) wins over its `role`, which wins over the worker leg. Each leg's tasks run as their own group (cloud cap for a cloud leg, one at a time on a second local server), priced, counted in the turn's cap, and the row carries `model` / `modelRole`. A second llama-server model is used only with `mixLocalModels: true`; otherwise the task runs on the worker leg and its row says so. `review` is the judge's model when `judgeProvider` is unset; `plan` does not switch the orchestrator. The `### fusion` block lists the role models only when some are configured.
[branch-workspace.ts](branch-workspace.ts) and [branch-merge.ts](branch-merge.ts) are branch isolation (ATO-946, `isolation: "worktree"`, default `"off"`): each run of tasks (a wave, a judge's retry) gets a workspace per task plus an untouched base, all from one snapshot of the working directory. In a git repo the snapshot is `git stash create` (HEAD when clean; the working tree, index and stash list are not touched) checked out as a detached `git worktree`, with untracked files copied and ignored directories symlinked; elsewhere it is a folder copy (clonefile on macOS); a tree too large to copy runs in place and every row says so. The worker's session, brief, write scope, declared inputs and declared-file check all point at its workspace (`RunWorkerTasksOptions.taskWorkspace`). After the wave each workspace is merged back in task order, file by file against the base: a file only the task changed is copied in, one the folder also changed is merged with `git merge-file`, anything else is a conflict that leaves the folder's file untouched, saves both sides under `.atomic-agent/fusion-merge/`, turns the row `needs_orchestrator` and returns a `merge-<id>` task in `details.merges` for the planner. A declared input the task removed or cut to under half its lines is refused at merge time. Failed, cancelled, timed-out and queued tasks are not merged. Workspaces are removed (`git worktree remove --force`, `git worktree prune`) in a `finally`, on abort and throw too.
[task-tree.ts](task-tree.ts) is the task tree (ATO-940, `taskTree.enabled`, default off; `maxDepth` 2, hard cap 3; `maxNodes` 24). Workers still never delegate: a worker that may split is told how in its brief and steered once at the half-budget hand-back or a cut first answer (`SPLIT_GRACE_STEPS` more steps), and ends its turn with a fenced `split_proposal`. The delegate validates it with `parseDelegateArgs` plus the depth, node and parent-files caps, namespaces ids as `parent/child`, runs the children through the same runner (turn caps, approval scope, child budgets clamped to the parent's), checks their contract and the parent's declared files, and closes the parent row on them. A refused proposal leaves the task `needs_orchestrator`. `details.taskTree` carries the nodes.
[run-checkpoint.ts](run-checkpoint.ts) and [run-resume.ts](run-resume.ts) let a run survive a restart (ATO-617): one JSON file per run under `<stateDir>/fusion-runs/` (not a table: the session store's schema and turn marks are pinned, and a checkpoint write must never fail a fan-out), written after every finished task (row, spend, side-effect tools as they start) and every wave, deleted on a normal end, kept as `interrupted` when the turn was stopped. A file whose process is gone or stopped is offered (`runtime.fusionRuns`, `/fusion` in the TUI) for 7 days. `fusion.delegate { resume: runId }` replays the checkpoint's own arguments: settled tasks are carried (a `cancelled` row is not settled), the rest run, the spend so far counts toward the turn's cap, and a task whose worker called anything outside the file tools and reads (`toolHasSideEffects`) is not re-run until `confirm: [taskId]`. Desktop has no offer yet.
