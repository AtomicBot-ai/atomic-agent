# Command execution

Status: current
Owner: src/sandbox/

Owns command jobs, output caps and process-tree cancellation. Preserve shell interpretation and explicit cancellation; dispatch approval lives in the caller wrapper.

Entry point: [command-runner.ts](command-runner.ts).

[command-env.ts](command-env.ts) builds the environment of an agent-run command: the agent's own environment minus secret-looking variables (names with KEY, TOKEN, SECRET, PASSWORD and similar, plus a list of known provider keys), with an explicit passthrough list (ATO-347). It is a deny filter rather than the MCP allowlist because a shell command needs the user's full toolchain environment. `os.shell.run`, `os.git.*`, hooks and skill scripts call it with the configured passthrough. It is also the default of `runCommand` and `startCommandJob` (ATO-175): a caller that passes no `env` (ripgrep, trash, process list/kill, curl, window scripts, capability probes) gets the filtered environment, never the raw `process.env`. A child that really needs a key gets an `env` built and passed explicitly by its caller: the subscription CLIs (`cli-child-env.ts`) and `gh auth token` do this. Read the root instruction route and the underlying domain instructions before cross-domain changes.

[command-toolchain-env.ts](command-toolchain-env.ts) adds, for `os.shell.run` only and after the filter, fixed non-interactive switches and the user's toolchain PATH (macOS `/etc/paths`, Homebrew, nvm, pyenv and similar folders that exist; never the login shell, whose rc files the agent can write), appended after the inherited PATH so nothing already found is shadowed (ATO-1252). It reads no variable back from the agent's environment except PATH.

[os-sandbox.ts](os-sandbox.ts) is Safe Mode's OS sandbox for `os.shell.run` (ATO-469, network switch ATO-472). Off by default; `ATOMIC_AGENT_SANDBOX=workspace` turns it on. The command is wrapped before spawn: macOS `sandbox-exec` with a Seatbelt profile built per call (paths passed as `-D` parameters, never spliced into the profile), Linux `bwrap`. Writes are allowed only under the session's working directory and temp; the model's `cwd` argument never widens this, and a working directory that is the home folder or above it (`~`, `/home`, `/`) is not writable at all (the policy lists it in `narrowedRoots` and the command notice says so), because it would expose every rc file and tool `bin` (ATO-1651). No shared package cache in the home folder is writable (ATO-1651): `npx` runs `~/.npm/_npx` as is, Maven and Gradle load jars from `~/.m2` and `~/.gradle`, cargo and Go build what is extracted in their caches, so a package planted there would run later outside the sandbox. [sandbox-cache-env.ts](sandbox-cache-env.ts) points the tools at a private cache under temp instead (`npm_config_cache`, pnpm, yarn, bun, `PIP_CACHE_DIR`, `UV_CACHE_DIR`, `GOMODCACHE`, `GOCACHE`, `CARGO_HOME`, `GRADLE_USER_HOME`, `XDG_CACHE_HOME`, and `-Dmaven.repo.local` appended to `MAVEN_OPTS`), for `os.shell.run` and sandboxed stdio MCP servers; that folder is made private to the user and never taken over from another owner or a link. Installs inside the sandbox start from a cold cache, so new packages need the sandbox network; Xcode builds need `-derivedDataPath` inside the working folder. Same rule as Codex CLI's `workspace-write` profile. Credential folders and files (`~/.ssh`, `~/.aws`, `~/.netrc`, shell history, ...) and the agent's state directory cannot be read, under their link path and their resolved path; a working folder inside one is reopened by itself, the rest stays hidden. Without network (`ATOMIC_AGENT_SANDBOX_NETWORK` not `on`) outbound IP connections, DNS lookups and URL opening are blocked; loopback IP stays open (on Linux it is the sandbox's own loopback, not the host's). On Linux the command also gets its own pid namespace (`--unshare-pid`): `/proc` lists only the sandbox's processes, so a host process's `/proc/<pid>/root` cannot be used to reach a hidden path. Local unix sockets differ by platform. macOS denies every one. On Linux `--unshare-net` blocks abstract sockets only, so [os-sandbox-sockets.ts](os-sandbox-sockets.ts) covers a fixed list of socket places that exist (ATO-1652): the user's runtime folder `/run/user/<uid>` and `XDG_RUNTIME_DIR` with an empty tmpfs (session D-Bus, systemd user manager, rootless Docker and Podman, GnuPG and keyring agents), `/tmp/.X11-unix`, `/tmp/.ICE-unix`, `/tmp/tmux-<uid>` and `/tmp/ssh-*`, and with `/dev/null` the system Docker, containerd, Podman, CRI-O, D-Bus, snapd, libvirt and LXD sockets, the Docker list, the exact `SSH_AUTH_SOCK` path and a `unix://` `DOCKER_HOST` or `CONTAINER_HOST`. A socket somewhere else is closed by [seccomp-unix-block.ts](seccomp-unix-block.ts) (ATO-2469, Claude Code sandbox-runtime's Linux approach): a classic BPF program, built in code, that refuses `socket(AF_UNIX)` (x86_64, x32, i386, aarch64 and 32-bit ARM tables), `socketpair(AF_UNIX)` of any type but stream and seqpacket (a datagram pair could still `sendto` a named datagram socket such as journald's `/dev/log`), the i386 `socketcall(SYS_SOCKET)` and `socketcall(SYS_SOCKETPAIR)` and `io_uring_setup` with `EPERM`, handed to `bwrap --seccomp 3` on a pipe (`fd3Input`, fed by [command-job-spawn.ts](command-job-spawn.ts)), never a file a command could rewrite in temp; stream and seqpacket pairs stay allowed (they are connected for good and reach no socket file). Hosts other than x64 and arm64 get no filter and keep the path masks only. A folder holding the working folder is never covered whole; its known sockets are covered one by one. The command also loses `SSH_AUTH_SOCK`, `DOCKER_HOST`, `CONTAINER_HOST` and the D-Bus and GnuPG agent variables. With network on, local sockets stay reachable on both platforms. Where no sandbox exists (Windows, Linux without `bwrap`) a command is refused with a message that says how to turn the mode off, never run unsandboxed. Not yet wrapped: skill scripts, git plumbing, hooks.

[sandbox-protected-paths.ts](sandbox-protected-paths.ts) keeps some paths read-only inside the sandbox's writable folders, because they run code later, outside the sandbox (ATO-2471; Claude Code sandbox-runtime's mandatory deny list, Codex's read-only `.git`): everything in a `.git` except the data git writes itself, so `config`, `config.worktree`, `hooks`, `info`, `commondir` and a linked worktree's `gitdir` (a `commondir` can point git at a copy of the repo with its own hooks); the hook folders in the work tree (`.husky`, `.githooks`, and the folder `core.hooksPath` names, read by [git-hooks-path.ts](git-hooks-path.ts) from the working folder's repo config and the global and system git config, along with the files those configs include) and the hook managers' `.pre-commit-config.yaml` and `lefthook.yml`; the shell rc files (`.bashrc`, `.zshrc`, `.profile` and the rest), `.envrc`, `.gitconfig`, `.gitmodules`, `.config/git`, `.config/fish`, `.vscode` and `.idea`. macOS denies them with fixed Seatbelt regexes at any depth (the `core.hooksPath` folder and included files as `-D` parameters); inside a `.git` only objects, refs, logs, the index, `HEAD` and git's other state files and their locks stay writable, so git still commits there, and no `.git` can be created, renamed or replaced (so `git init` and `git clone` fail inside the sandbox). Linux searches the working folders three levels deep and binds each one that exists read-only, each `.git` whole (so git commands that write the repo fail inside the sandbox, as in Codex), and makes the folders above them mount points so they cannot be renamed away; a protected path that does not exist yet is not covered on Linux (ATO-2787). Not covered: other work-tree files that run later (package.json scripts, a Makefile, CI workflows, a script a git config option already names).

[secret-placeholders.ts](secret-placeholders.ts) reads and fills `{{secret:NAME}}` in a command (ATO-476); a malformed placeholder or a missing name is an error, and a line a shell parses takes only plain token characters from a value. [resolved-secret-values.ts](resolved-secret-values.ts) holds, in memory only, every value resolved from a secret reference, with its base64, base64url and URL-encoded forms; the secret detector masks them on every call whatever list its caller passes, and [capped-output.ts](capped-output.ts) hides a piece of one left on either side of its dropped middle.
