# GitHub API integration

Status: current
Owner: src/github/

Owns API/auth helpers for tool and UI consumers. Keep credentials out of persisted remote URLs and command diagnostics; use explicit API error parsing.

Entry point: [github-api.ts](github-api.ts).

CI autofix (ATO-2331): [github-checks.ts](github-checks.ts) folds check runs and commit statuses on a PR head into one verdict (newest run per name; the combined status state is ignored because GitHub reports `pending` for a commit with no statuses); [github-log-tail.ts](github-log-tail.ts) keeps the last 256 KiB of an Actions job log while reading, then the cleaned last lines plus `##[error]` lines. [pr-autofix-guard.ts](pr-autofix-guard.ts) holds the push rules (open PR, head branch in the same repo, never the default, a protected name or the base) and the attempt cap (default 3 per PR head; a push by a person restarts it, a GitHub head still at the sha seen before our push does not); [pr-autofix-store.ts](pr-autofix-store.ts) keeps that state in `<stateDir>/pr-autofix/state.json`, on the trust list (a write asks as `trust_config`, a read as `state_secret`; the worktrees beside it are not); the worktree folder is always derived, never read from that file. The tools are `github.pr.checks` and `github.pr.autofix` in `src/tools/github/`; the loop is the `pr-autofix` starter skill.

Conflicts, review comments and the watch (ATO-2516): check runs and statuses are read up to 10 pages of 100 ([github-checks-api.ts](github-checks-api.ts)); the PR head carries GitHub's merge check (`mergeable` / `mergeable_state: dirty`). [github-pr-feedback.ts](github-pr-feedback.ts) reads review bodies (changes requested or commented), inline review comments and conversation comments, and keeps only the repo's team (`author_association` OWNER, MEMBER, COLLABORATOR), never bots, never outdated lines, newest 20; the rest is counted, not shown. A conflict is fixed by merging the base into the autofix worktree (`merge-base`), never a rebase, so the push stays a fast-forward. [pr-autofix-watcher.ts](pr-autofix-watcher.ts) is a scheduler sidecar (leader only): every minute at most it reads the state file, and for each enabled PR with a `watch` ([pr-autofix-watch-state.ts](pr-autofix-watch-state.ts), every 5 to 120 min, default 10) it reads the PR with plain REST calls, no model. It files a task in the chat that turned the watch on (one attempt, optional Telegram or push report) only for CI failing on a head not handed over yet, a conflict on a head not handed over yet, or team feedback newer than the last round; never while the previous round's task is open or the PR is paused at its cap; a closed PR ends its watch. The watch is written before the task is filed, and the task text carries no GitHub text. Writes to the state file go through `AutofixStore.update` (one at a time per file in a process) so the tool's counter and the watcher's bookkeeping never undo each other. `prepare` and `merge-base` widen the session's read scope to the PR's worktree. Not done: replies on GitHub (public text under the user's name), and refusing `os.git.push` to the default branch while autofix is on.

Read the root instruction route and the underlying domain instructions before cross-domain changes.

Checks: `npx vitest run src/github` when tests are present; `npm run lint`; `npm run docs:check`.
