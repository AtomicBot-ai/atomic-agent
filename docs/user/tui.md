# Using the terminal interface

Status: current
Owner: src/tui/

Launch `atomic-agent tui --cwd /path/to/work`. The TUI presents multi-turn chats, approvals, models, tools, memory, tasks and integration controls. Use `/help` to discover the installed command set instead of relying on a historical shortcut list. `/settings <words>` finds any config setting with its default and description; the full list is the [settings reference](settings-reference.md).

A selected chat and an actively running turn can be different sessions. Observe their status before cancelling or deleting work. Provider/model changes affect live runtime resolution; managed local downloads/server lifecycle have their own status.

In the composer, Local mode has the backend and model controls: Atomic Chat Core runs local models and is not a choice there. When Core cannot be installed or started, the Models tab shows what happened with one action: `R` downloads it again. The standalone llama.cpp server is a support-only fallback that the app does not offer: `/model engine llama-server` (or `atomic-agent models engine llama-server`) selects it when support asks you to, and `/model engine atomic-core` switches back. Fusion has an engine/provider and model control for each role, with the swap control between orchestrator and worker. Each model list belongs to its own role. A local seat is labelled **Local**. There is one managed local slot: use swap to move it between roles. Stop a loaded local model before changing its engine. A pending route change holds message submission until it finishes.

`/goal <criteria>` keeps a chat working until an acceptance list is met: write the items one per line or split by `;`, and add shell checks that must pass with `/goal check add <cmd>` (or a `check: <cmd>` item). After each round the checks run, then the model judges every item; open items start the next round, up to 10 rounds by default. `/goal tokens <n>` (for example `500k`, or `off`) caps the tokens the goal may use across all its rounds; a new goal starts with `agent.goal.maxTokens` from the config (default `0`, no cap). `/goal status` shows where it stands, `/goal pause`, `/goal resume` and `/goal clear` control it. The goal is saved with the chat and survives a restart; a goal that was running when the agent stopped waits for `/goal resume` instead of continuing on your next message.

Personas are named instructions you add to the agent's own: define them under `agent.personas.definitions` in the config file (each has `instructions` and an optional `style`). `/persona` lists them and shows which one a new session in this folder would use, `/persona use <name>` picks one for everywhere, and `/persona bind <name>` ties one to the current folder (the closest bound folder wins over `use`). `default` in place of a name turns it off. The `ATOMIC_AGENT_PERSONA` environment variable wins over both. A chat keeps the persona it started with, so a switch applies from the next session (`/new`).

`/vim` turns on vim keys in the composer (off by default, saved as `tui.vimMode`; `/vim on` and `/vim off` set it). A message starts in INSERT, shown next to Send. Esc goes to NORMAL, where `h j k l w b e 0 $ ^ gg G` move, `i a I A o O` go back to typing, `x dd dw cw cc D C yy p P` edit (operators take any of those motions, and counts work: `3w`, `d2w`, `2dd`) and `u` undoes. In NORMAL, Enter still sends. A single Esc there does nothing (it still closes the palette and, during a turn, arms the abort), and Esc Esc clears the draft into prompt history, so Up brings it back. The Esc that leaves INSERT never aborts a turn, stops context maintenance or answers an approval. Arrows, Tab, Ctrl chords and pastes behave as without vim.

The interface language is set by `tui.language` in the config file: `auto` (default), `en` or `ru`. With `auto` the TUI uses the `ATOMIC_AGENT_LANG` environment variable, then the system locale (`LC_ALL`, `LC_MESSAGES`, `LANG`, so `ru_RU.UTF-8` gives Russian), then English. For example `atomic-agent config set tui.language ru`, or `ATOMIC_AGENT_LANG=ru atomic-agent tui` for one run. It takes effect at the next start. Only the first-run setup screens are translated so far; the rest of the TUI is in English.

The keyboard and mouse share the same UI transitions. Terminal size/capabilities affect layout and modified keys. The runtime restores terminal modes when the interface exits.
