## Где мы находимся и что меняем

Vitest выполняет тесты после преобразования TypeScript, но это не доказывает корректность их типов. Production lint исключает тесты. Отдельный tsconfig.test.json уже имеет долг и не выбирает TSX; изменение интерфейса поэтому может ломать тестовые fixtures без проверяемой обратной связи в PR.

Цель: проверять весь тестовый контекст, запрещать новые ошибки типов и постепенно уменьшать старые, явно отделяя карантин runtime-тестов от типового долга.

Изменения: tsconfig.test.json, package.json, .github/workflows/test.yml, новые scripts/check-test-types.mjs и docs/testing/, затем небольшие исправления тестовых fixtures в затронутых областях. Перед работой читать scripts/AGENTS.md и инструкции области каждого изменяемого теста. Runtime-алгоритмы, публичные интерфейсы, конфигурационные defaults, переносы модулей, зависимости и eval-кампании в этот этап не входят. Изменение runtime, необходимое для исключённого теста, выносится в отдельную задачу с собственным обоснованием.

## Измеренный исходный долг

Проверка 2026-10-06, установленный TypeScript 5.9.3 из текущего lockfile:

- `npx tsc -p tsconfig.test.json --noEmit --pretty false`: 889 диагностик, 2125 корневых файлов программы; в программе нет ни одного test.tsx.
- Та же конфигурация с include src/**/*.ts и src/**/*.tsx, без сохранения изменения: 2359 корневых файлов, 104 test.tsx, 971 диагностика. Прирост — 82 диагностики TUI. В полной выборке TUI даёт 547 диагностик; далее agent 80, llm 60, tools 41, memory 38, prompt 30, runtime 24, mcp 23, local-llm 22.
- Среди ошибок есть TS6059 о файле вне rootDir, устаревшие обязательные поля mocks, сигнатуры vi.fn и несовпадение shapes. Это разные причины; общий cast не устраняет их.
- PR CI проверяет production types и выполняет Vitest с двумя исключениями: src/sidecar/send-message-concurrency.test.ts и src/tui/local-models/local-models-orchestrator-auto-update.test.ts.

Эти числа — исходное измерение, а не готовая разрешающая база. Перед фиксацией baseline снять их повторно после изменения include/rootDir. Пути, коды и полный текст диагностик временного измерения сохранены в /tmp/atomic-stage01-types-coverage.json; долговременная база создаётся при реализации, а не копируется из этого временного файла вслепую.

## Выбор подхода

Рекомендуется полная выборка с базой существующих диагностик и строгим запретом новых. Безусловный tsc сейчас сделает все PR красными; исключение проблемных каталогов снова скроет ошибки интерфейсов. База оставляет долг видимым, а production lint продолжает требовать ноль production-ошибок.

База не должна ограничиваться общим числом ошибок: исправление одной не даёт права внести другую. Не использовать @ts-nocheck, массовые any, отключение strict/noUncheckedIndexedAccess или расширение exclude ради зелёной проверки.

## Последовательность небольших изменений

### 01a. Полное покрытие и запрет роста

1. Включить src/**/*.ts и src/**/*.tsx в tsconfig.test.json; оставить тесты в выборке. Проверить TS6059 из-за импорта scripts: для noEmit-программы выбрать rootDir, охватывающий реально импортируемые файлы, без скрывающего исключения. Зафиксировать фактический набор корневых файлов и эффективные compiler options.
2. Добавить scripts/check-test-types.mjs на существующем TypeScript API. Получать конфигурацию через штатный TS parser, собирать синтаксические и семантические ошибки, печатать понятные локальные пути. Не запускать тесты, серверы, загрузки или внешние API при проверке типов.
3. Сохранить docs/testing/test-type-debt.json: версию компилятора, относящиеся к проверке compiler options, диагностические записи и их кратность. Запись различает путь, код, нормализованное сообщение и устойчивый фрагмент места ошибки; номера строк служат навигации, а не единственным идентификатором. Не сводить ошибку к числовому бюджету области. Две одинаковые ошибки должны учитываться отдельно по кратности.
4. Режим проверки падает при новой диагностике, утрате ожидаемого покрытия TSX или несовместимом изменении настроек проверки. Исправленная ошибка также требует уменьшить базу: устаревшие разрешения не сохранять молча. Режим уменьшения разрешает только удаление уже исправленных записей; рост долга не принимать автоматическим update.
5. Добавить команды `typecheck:tests` (база долга) и `typecheck:tests:raw` (полный tsc с ожидаемым ненулевым результатом до очистки). Включить первую в стандартную PR job рядом с production typecheck. Первичная база требует просмотра diff, а не механического одобрения 971 ошибки.
6. Проверить реализацию временными fixtures: новая ошибка в TSX обнаруживается; добавление второй одинаковой ошибки обнаруживается; сдвиг строк не становится новой ошибкой; исправление требует уменьшения базы; отключение TSX и ослабление настроек отклоняются. Валидный новый тест без ошибок проходит. Все fixtures удаляются.

### 01b. Локальный эквивалент CI и карантин

1. В docs/testing/local-ci.md описать production lint, docs:check с self-test, typecheck:tests и Vitest с теми же исключениями, что CI. Команды должны запускаться в указанной среде и возвращать ненулевой код при сбое.
2. Записать два исключения в docs/testing/quarantine.json: точный путь, владелец подсистемы, основание, команда воспроизведения, актуальный результат, условие возврата и ссылка на существующую задачу #203. Комментарии CI — гипотеза для сверки, а не доказательство сегодняшнего поведения.
3. Для send-message-concurrency отдельно выяснить назначение третьего inference: дополнительный runtime вызов и неверный mock/expectation требуют разных исправлений. Для auto-update проверить границу mock транспорта/daemon и unhandled errors; число “passed” при ненулевом exit не считать успехом.
4. Перед воспроизведением проверить изоляцию временного state и всех daemon/network границ. Не запускать реальный сервер как побочный эффект unit-теста. Если для воспроизведения нужны новые mocks, это отдельное небольшое изменение теста, а не объявление старой проверки зелёной.
5. Связать registry с фактическими CI exclusions, чтобы новый skip без записи и запись без соответствующего skip обнаруживались. Описать job без optional canvas как отдельный сценарий: не удалять пакеты в обычной рабочей установке ради локальной проверки, использовать отдельную временную установку.

### 01c. Первое уменьшение долга

Начать с MCP fixtures, поскольку следующая организация TUI начинается с MCP: по исходному измерению там 23 диагностики. Выбрать подтверждённые группы missing fields/устаревших mocks, восстановить реальные shapes и выполнять существующие тесты. После каждой небольшой группы уменьшить базу, не снижая проверяемую семантику.

Общие fixture builders вводить только для повторяющегося реального контракта; проверять их через satisfies или явный тип без any. Не превращать этот пакет в перестройку MCP UI. Следующие группы — transport/provider fixtures и TUI по конкретной функции; их состав уточнять по результатам первого уменьшения. Ноль ошибок во всём проекте не является условием первого включения проверки.

## Критерии завершения

- Все 104 существующих test.tsx попадают в программу; новый TSX-файл автоматически попадает в проверку. Production lint остаётся строгим и зелёным.
- typecheck:tests проходит только при соответствии явно просмотренной базе; негативные проверки подтверждают запрет новой ошибки, дубликата и потери покрытия.
- Первая согласованная группа тестовых fixtures исправлена, её существующие тесты проходят, база уменьшена. Области без записей долга не получают новых разрешений автоматически.
- Локальные команды и CI используют одинаковые ограничения; оба исключённых runtime-теста имеют владельца, воспроизводимые результаты и конкретный критерий возврата. Карантинные тесты не объявляются проходящими до отдельной проверки.
- docs:check, его self-test, production lint и затронутые тесты проходят; diff не содержит незаявленного изменения runtime или ослабления проверок.

После этих критериев этап становится verified. Затем создаётся план 02 о границах зависимостей с учётом уже работающего typecheck и выявленных seam-тестов; реорганизация TUI до этого не начинается.
